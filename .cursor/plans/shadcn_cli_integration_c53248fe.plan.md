## Root causes (why the UI looks wrong today)

- No `components.json`, no `src/lib/utils.ts` — the shadcn CLI was never run; the `ui/` files are hand-written copies.
- `tw-animate-css` is not installed, so `data-[state=open]:animate-in`, `fade-in-0`, `fade-out-0` used in [dialog.tsx](vscode-ui/src/components/ui/dialog.tsx) and [context-menu.tsx](vscode-ui/src/components/ui/context-menu.tsx) render as no-ops. This is the main reason dialog/context-menu look flat.
- [tailwind.css](vscode-ui/src/styles/tailwind.css) skips preflight and only defines `--color-*` tokens. shadcn expects the full v4 contract (`@import "tailwindcss"`, `@theme inline` mapping, plus `--background/--foreground/--card/--popover/--muted/--border/--input/--ring/--primary/--destructive/--sidebar-*/--radius`).
- `lucide-react` is pinned at `^1.9.0` (not a real version); `shadcn add` will pull a valid one.

## Target state

- `src/lib/utils.ts` owns `cn`; `src/utils/classNames.ts` becomes a thin re-export so existing consumers don't break.
- `src/styles/tailwind.css` becomes a standard shadcn v4 file: `@import "tailwindcss"; @import "tw-animate-css";` + `@theme inline { ... }` + `:root { ... }` / `.dark { ... }` filled with a VS Code dark palette so the app keeps its current look.
- `src/components/ui/{button,input,dialog,alert-dialog,context-menu,dropdown-menu,tooltip,separator}.tsx` are generated by `shadcn add` (no manual editing).
- `confirm-dialog.tsx` rewritten to use `AlertDialog` + `Button` (shadcn-idiomatic); `icon-button.tsx` becomes a tiny wrapper around `Button` with `size="icon"` + `variant="ghost"`.
- Preflight is enabled; the existing layout CSS is patched where it collides.

## Steps

### 1. Pre-CLI prep

- Update [vscode-ui/tsconfig.json](vscode-ui/tsconfig.json) and [vscode-ui/tsconfig.app.json](vscode-ui/tsconfig.app.json) to add `"baseUrl": "."` (paths already correct). [vite.config.ts](vscode-ui/vite.config.ts) already has the `@` alias.
- Delete the manual files so the CLI's output is authoritative:
  - `src/components/ui/dialog.tsx`
  - `src/components/ui/context-menu.tsx`
  - `src/components/ui/input.tsx`
  - Keep (temporarily) `confirm-dialog.tsx` and `icon-button.tsx` — we rewrite them after init.

### 2. Run the shadcn CLI (from `vscode-ui/`)

```bash
yarn dlx shadcn@latest init          # prompts: style=new-york, base=neutral, css vars=yes
yarn dlx shadcn@latest add \
  button input dialog alert-dialog \
  context-menu dropdown-menu tooltip separator
```

The CLI will:
- Create `components.json`
- Create `src/lib/utils.ts` (exports `cn`)
- Rewrite `src/styles/tailwind.css` (we'll customize after)
- Install `tw-animate-css`, `class-variance-authority`, `clsx`, `tailwind-merge`, correct `lucide-react`, and the Radix packages the components need
- Drop each component file into `src/components/ui/`

### 3. Re-apply the VS Code dark theme

Customize the generated `src/styles/tailwind.css` so the palette stays VS Code-like. Sketch:

```css
@import "tailwindcss";
@import "tw-animate-css";

@custom-variant dark (&:where(.dark, .dark *));

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-popover: var(--popover);
  --color-popover-foreground: var(--popover-foreground);
  --color-border: var(--border);
  --color-input: var(--input);
  --color-ring: var(--ring);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-accent: var(--accent);
  --color-accent-foreground: var(--accent-foreground);
  --color-destructive: var(--destructive);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --radius-sm: calc(var(--radius) - 2px);
  --radius-md: var(--radius);
  --radius-lg: calc(var(--radius) + 2px);
}

:root {
  --background: #1e1e1e;
  --foreground: #cccccc;
  --popover: #252526;
  --popover-foreground: #cccccc;
  --border: #454545;
  --input: #3c3c3c;
  --ring: #007acc;
  --primary: #007acc;
  --primary-foreground: #ffffff;
  --accent: #094771;
  --accent-foreground: #ffffff;
  --muted: #2a2d2e;
  --muted-foreground: #8c8c8c;
  --destructive: #e51400;
  --radius: 0.375rem;
}
```

Then force the `.dark` class on `<html>` (or just rely on `:root` since the app is always dark).

### 4. Patch plain-CSS impacted by preflight

Preflight resets margins, list styles, heading sizes, and `button { background: transparent; border: 0; font: inherit; }` globally. Audit impact on:
- [src/styles/global.css](vscode-ui/src/styles/global.css) — drop the now-redundant `*` reset and `button` reset.
- [src/components/Sidebar/CollectionTree.css](vscode-ui/src/components/Sidebar/CollectionTree.css), [Sidebar.css](vscode-ui/src/components/Sidebar/Sidebar.css), [Header.css](vscode-ui/src/components/Header/Header.css), [ActivityBar.css](vscode-ui/src/components/ActivityBar/ActivityBar.css), [Workbench.css](vscode-ui/src/components/Workbench/Workbench.css), [EditorArea.css](vscode-ui/src/components/EditorArea/EditorArea.css) etc. — spot-check button/list/heading styles; anything that implicitly relied on default UA margins gets an explicit rule.

- `src/components/ui/icon-button.tsx` -> thin wrapper: `<Button variant="ghost" size="icon" data-active={active}/>`.
- [NodeContextMenu.tsx](vscode-ui/src/components/Sidebar/NodeContextMenu.tsx) — no changes; the Radix API exposed by the generated `context-menu` is identical.

  - [SidebarHeader.tsx](vscode-ui/src/components/Sidebar/SidebarHeader.tsx)
